The WMS-tier inbound dock workflow of the warehouse-systems platform
(ADR 0001): the supplier's advance ship notice (**ASN**), the carrier's
booked **dock appointment** and the counted **receipt**, with the
discrepancies found when the receipt closes (ADR 0002). It decides nothing
about where received goods go; Good lines are handed to inventory-storage
as events (ADR 0003) and stow stays an RF action there.

Every `POST` requires an `Idempotency-Key` header (fleet REST API
guideline): a missing key is a 400 `idempotency-key-required`, a retry with
the same key and request (method, path, body) replays the original response
with `Idempotency-Replayed: true`, the same key with a different request is
a 409 `idempotency-key-reused`. Lifecycle transitions are transition
resources: `POST /asns/{asnNumber}/cancellations`,
`/appointments/{appointmentId}/check-ins`,
`/appointments/{appointmentId}/cancellations` and
`/receipts/{receiptId}/closures`.

Mutable resources carry a `version` (starts at 1, +1 per accepted change)
and a matching strong `ETag: "<version>"` header. A transition `POST` may send
`If-Match`; a stale value is a 412 `version-mismatch`, and a write that
loses a race at the database is a 409 `concurrent-modification`.

Accepted changes are published as CloudEvents on
`warehouse.inbound-receiving.events` through a transactional outbox (see
`apis/asyncapi.yaml`); sibling contexts keep a local copy and never call
this API at request time.

Errors are RFC 7807 problem documents (`application/problem+json`) with
`type = https://errors.inbound-receiving.warehouse-systems.dev/<slug>`.
The slug catalogue: `malformed-request`, `invalid-query`,
`idempotency-key-required`, `idempotency-key-invalid`,
`idempotency-key-reused`, `invalid-limit`, `invalid-cursor`,
`unknown-query-parameter`, `invalid-asn-number`,
`invalid-supplier-ref`, `asn-requires-lines`, `invalid-line-no`,
`duplicate-sku`, `invalid-sku`, `invalid-quantity`, `invalid-reason`,
`invalid-appointment-id`, `invalid-receipt-id`, `invalid-door-code`,
`invalid-carrier`, `invalid-window`, `window-in-past`,
`appointment-requires-asns`, `duplicate-asn-number`, `invalid-condition`,
`asn-not-found`, `appointment-not-found`, `receipt-not-found`,
`asn-already-exists`, `asn-in-progress`, `asn-terminal`,
`asn-not-receivable`, `appointment-not-booked`,
`appointment-not-checked-in`, `outside-check-in-window`,
`door-window-overlap`, `receipt-already-open`, `receipt-closed`,
`unknown-sku`, `unknown-dock-door`, `unknown-asn`, `unknown-appointment`,
`asn-not-on-appointment`, `line-not-on-asn`, `invalid-owner-ref`,
`invalid-carton-kind`, `invalid-carton`, `invalid-sscc`, `invalid-gtin`,
`unsupported-gtin`, `invalid-scan-kind`, `invalid-scan`, `invalid-cases`,
`invalid-counted-contents`, `counted-contents-not-mixed`,
`counted-sku-unknown`, `carton-not-found`, `duplicate-sscc`, `homogeneous-carton-mixed`, `carton-contents-mismatch`,
`scan-kind-mismatch`, `unsupported-pack-level`, `version-mismatch`,
`concurrent-modification`, `resource-not-found` (a NUL character in the
request path), `dependency-unavailable` (`/readyz` while Postgres or Kafka
is unreachable), `internal-error`. A NUL (U+0000) in a JSON body is a 400
`malformed-request`.

Lists use cursor paging: `limit` (1 to 500, default 100) and the opaque
`cursor` that is the previous page's `nextCursor`; a response without
`nextCursor` is the last page. There is no authentication layer (fleet
decision 2026-09-11).
